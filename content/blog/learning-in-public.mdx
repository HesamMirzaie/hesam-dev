Learning in public does not require publishing a polished tutorial every time you encounter something new. It can be a small practice: record the question, the useful answer, and the edge you have not explored yet.

## Start with a question

Notes become easier to revisit when their title preserves the problem that led to them. Instead of collecting definitions, write down the moment where a concept became useful.

For example, an early note about rendering can begin with this question:

```ts
const nextStep = question => investigate(question)
```

## Keep the boundary visible

Every note should distinguish between what you have verified and what you still want to test. That makes it more useful to future you—and more honest for anyone else reading it.

1. Explain the core idea in your own words.
2. Include one small example.
3. Add a follow-up question when the idea is incomplete.

The goal is not to look finished. The goal is to make the next learning session start closer to the answer.
